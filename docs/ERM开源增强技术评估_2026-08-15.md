# ERM 开源增强技术评估（对照主仓库）

- **日期**：2026-08-15
- **对照代码**：`D:\_Work\01_Projects\enterprise-risk-assessment`
- **已装依赖**：Flask、openpyxl、python-docx、reportlab、RapidOCR、pypdf、jsonschema、pandera、pandas、APScheduler、NumPy、SciPy、SALib、Pillow
- **原则**：评分大脑自研；开源只补平台与量化；LLM 不做分；不整体替换为英文 GRC

上一版审计里的开源表是**方向清单**。本文件是对照主仓库后的**裁决**：每项给出许可证、与现栈关系、适配度、采用/延后/不用、工作量。

---

## 1. 总裁决（先看这里）

| 裁决 | 技术 | 为何现在这样判 |
|------|------|----------------|
| **已在仓库，先用好** | RapidOCR、APScheduler、NumPy、pandas/pandera、jsonschema | 不要再换栈；NumPy 尚未用于蒙特卡洛 |
| **立刻采用（咨询路径）** | SciPy、SALib、NetworkX、Cytoscape.js | 体量小、许可证友好、直接补「方法穿帮」点 |
| **立刻采用（数据，非开源）** | 天眼查/企查查/公示系统 API | 开源补不了权威工商司法；动态性最大杠杆 |
| **企业路径采用，复用已有** | PostgreSQL + MinIO；身份用 EnterpriseRiskAI JWT 或 Casdoor | 不要在 Flask 里重造用户系统 |
| **延后** | PyMC/pgmpy、OpenSPG、LlamaIndex、TimescaleDB、Prefect、Unstructured | 现有模块未吃透前上这些是叠床架屋 |
| **借鉴对象、不迁系统** | eramba / SimpleRisk / OpenGRC | 只要控制库/签批模型 |
| **默认不用** | OpenQuake/CLIMADA、OpenCTI、用 LLM 打分、整体替换 GRC | 场景未到或会毁掉现有 IP |

**适配度口径**：5=可直接嵌入现 Flask；4=小改可接；3=要新服务；2=运维重；1=替换产品。

## 2. 主仓库已有开源：发挥度

| 组件 | 许可证 | 现状 | 发挥度 | 下一步 |
|------|--------|------|--------|--------|
| RapidOCR + pypdf | Apache-2.0 | `ocr_engine.py` / 证据抽取 | 中 | 保持；不必先上 Unstructured |
| APScheduler | MIT | `sync_scheduler.py` | 中 | **不要**立刻换 Prefect；先把任务结果落库 |
| NumPy | BSD | `risk_quant.py` 抽样 | **高（C4 已用）** | 已停用 `random.gauss` |
| pandas / pandera / jsonschema | BSD / Apache | ERP 校验 | 中 | 继续做外部 JSON 门禁 |
| Chart.js 4.4 | MIT | 仪表盘/报告图 | 高 | 网络图另加 Cytoscape.js，不必换 ECharts |
| Flask + Jinja | BSD | 整站 | 高 | 保持；报告页不重写成 SPA |

结论：开源增强的第一刀不是「再装一堆库」，而是 **把已装的 NumPy / RapidOCR / APScheduler 用到报告可信度上**。

## 3. 量化与不确定性

| 候选 | 许可 | 适配 | 裁决 | 说明 |
|------|------|------|------|------|
| **SciPy** | BSD | 5 | **已上线 · C4** | `scoreatpercentile` 输出评分分位 |
| **SALib** | MIT | 5 | **已上线 · C4** | Morris μ* 排出驱动综合分的前 5 个维度 |
| copulas (SDV) | MIT | 4 | 延后到有 10+ 次历史快照 | 现在维度独立高斯已经过度宣称；先独立敏感性，再相关结构 |
| chaospy | MIT | 4 | 备选 copulas | 多项式混沌，样本少时有用，非第一优先 |
| **PyMC** | Apache-2.0 | 3 | 延后 | 真后验需要历史与先验设计；现 `risk_bayesian` 是两次评分加权 |
| NumPyro | Apache-2.0 | 3 | 与 PyMC 二选一 | JAX 部署重于当前 Flask |
| **pgmpy** | MIT | 4 | 延后到 C3 之后 | 把现有风险集群做成 DAG；须先有独立 P×I，否则图是假的 |
| OpenQuake | AGPL-3.0 | 2 | **默认不用** | AGPL 会传染产品许可；仅场址地震客户且可隔离进程时再议 |
| CLIMADA | GPL-3.0 | 2 | **默认不用** | 同上；TCFD 章先降级为定性，避免 GPL 进主程序 |

CVaR 写在 1–4 分上，任何库都救不了文案。采用 SciPy/SALib 的前提是：**分数轨改叫「评分不确定性」，金额轨可关。**

## 5. 动态数据（开源的边界）

开源**不能**提供中国企业司法/工商权威源。

| 来源 | 类型 | 裁决 |
|------|------|------|
| 国家企业信用信息公示系统 / 裁判文书 / 失信 | 公共或半公共 | 能爬则合规封装；不能则走商业 API |
| 天眼查 / 企查查 / 汉得 MCP | **商业** | **已上线适配层 · C5**；无 Key 时报告标明「未接外部源」，DEMO 用样例 |
| GDELT | 开放数据 | 舆情补充，英文与噪声大，作辅源 |
| handaas enterprise-risk-mcp-server | 字段模型可参考 | 抄 schema，不绑定其商业账号 |

## 7. GRC 产品：借鉴 vs 替换

| 产品 | 许可 | 裁决 |
|------|------|------|
| eramba Community | 开源社区版 | **借鉴对象模型**（控制、证据、残余风险接受）；UI 自研 |
| SimpleRisk Core | GPLv3 | **不迁、不链进主程序**；可人工对照字段 |
| OpenGRC | 视发行版 | **不替换** 20 维中文规则 + 18 章报告 |
| OpenTRICK | 开源 | ISO 27001 偏信息安全，不是企业全面 ERM |
| Open Policy Agent | Apache-2.0 | 延后；先用 Python 门禁（honesty 已是） |

## 8. 明确不用（除非客户合同写明）

- 用大模型替代 `risk_engine` 打分
- OpenCTI / MISP / TheHive（无 SOC 对接需求）
- OpenQuake / CLIMADA 进主 Flask（许可 + 场景）
- 为「看起来更 AI」引入第二套打分器

---

## 9. 建议引入顺序（与 C/E 实施项对齐）

1. **C4 文案 + NumPy/SciPy/SALib**（已有 NumPy，增量最小）
2. **C5 工商司法适配**（商业 API，开源只写 connector）
3. **NetworkX + Cytoscape.js**（第十六章可交互）
4. **E1 身份**：优先 ERA JWT，否则 Casdoor
5. **E2 PostgreSQL + MinIO 客户端**
6. 有 3 次以上快照后再谈 pgmpy / copulas
7. 有制度语料后再谈 LlamaIndex 或 ERA 知识服务
8. 有股权/担保穿透需求再评估 OpenSPG（独立服务）

工作量粗估：步骤 1–3 合计约数天；4–5 约一周；6–8 按售卖单独立项。
